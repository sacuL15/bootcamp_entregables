1. Explica el flujo completo desde que un admin hace login hasta que puede agregar un plato. Menciona cada archivo que participa y qué hace cada uno.
R= El flujo completo sería el siguiente:
- auth.service.js: Cuando un admin hace login usando Thunder Client, comprueba los 2 datos: el email, si no existe el usuario y la contraseña, si no coincide. Por último, genera un Token encriptado si ingresa los datos correctamente.
- verifyToken.js: Cuando el admin desea realizar alguna modificación al menú con POST/ menu, tiene que ingresar con el Token generado y copiarlo en header, Authorization: Bearer Token. Este archivo es el middleware de ese Token y verifica si esta correcto o se modifico o venció para realizar los cambios.
- auth.sontroller.js: muestra los códigos de estados 201 (se creo un nuevo usuario) y 400 (se intenta duplicar el usuario) en register y 200 (se genera un token) y 401 (token modificado o ya se venció) en login.
- auth.router.js: Define las rutas que tomara cada función y se exportarán al sitio, app.js.

2. ¿Por qué bcrypt.compare() puede verificar la contraseña si el hash es irreversible? ¿Qué está haciendo internamente?
R= bcrypt.compare() funciona porque el hash generado por bcrypt incluye el salt y el costo. La función toma esos valores, vuelve a hashear la contraseña ingresada y compara el resultado con el hash almacenado. No necesita desencriptar nada, ya que el hashing es un proceso irreversible.

3. Si alguien roba un token JWT válido, ¿qué puede hacer con él? ¿Qué mecanismo del sistema limita el daño? ¿Qué agregarías para hacerlo más seguro?
R= Un atacante con un JWT válido puede acceder a rutas protegidas como si fuera el usuario autenticado. En nuestro código, el daño se limita por la expiración de 1 hora y la verificación de la firma del token. Para mejorar la seguridad, se recomienda usar tokens de corta duración (por ejemplo, 5 minutos= '5m') con refresh tokens y mecanismos de revocación de tokens. También sería recomendable no usar una clave secreta por defecto ('clave_desarrollo') en producción y asegurarse de que provenga de variables de entorno seguras.
